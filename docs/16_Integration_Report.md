# Отчёт об интеграции SportShop

## Структура проекта

```text
SportShop/
├── src/
│   ├── __init__.py
│   ├── catalog.py
│   ├── cart.py
│   ├── orders.py
│   ├── analytics.py
│   └── storage.py
├── tests/
│   ├── __init__.py
│   ├── test_catalog.py
│   ├── test_cart.py
│   ├── test_orders.py
│   ├── test_analytics.py
│   └── test_integration.py
├── docs/
├── data/products.json
├── main.py
└── build.py
```

## Выделенные модули и импорты

- `src/catalog.py`: низкий остаток, поиск, группировка по категориям, средняя цена.
- `src/cart.py`: добавление, удаление и обновление позиции, расчёт суммы; импортирует `_stock` из `src.catalog`.
- `src/orders.py`: создание, печать и хранение заказов; импортирует `cart_total` из `src.cart`.
- `src/analytics.py`: общая выручка, самый продаваемый товар, средняя сумма заказа.
- `src/storage.py`: чтение и запись списка товаров в JSON.
- `main.py` связывает модули импортами `from src...` и показывает рабочий сценарий.

## Проверки интеграции

`tests/test_integration.py` проходит полный цикл: загружает каталог из `data/products.json`, добавляет товар размера 40 в корзину, создаёт заказ, сохраняет его в JSON, загружает обратно и сравнивает сумму. Всего проект содержит 14 модульных и интеграционных тестов.

## Найденная несовместимость

В учебной проверке ключ `name` в позиции корзины временно заменялся на `product`. Интеграционный тест выявлял ошибку при создании заказа. Ключ восстановлен; детали описаны в `docs/15_Integration_Errors.md`.

## Сборка

`build.py` проверяет Python 3.10+, наличие файла данных, запускает все тесты и только при их успешном завершении запускает `main.py`. Для выполнения из корня проекта: `python build.py`.

Полный фактический вывод команды сохранён в корневом файле `BUILD_OUTPUT.txt`.
